# Test Deploy

Ship it, see it, trust it.

Test Deploy is a calm, technical brand. It should feel like a reliable tool: precise, quiet, and clear about status. This is a starter system with no source material behind it, so every value here is a first pass to refine.

## Content fundamentals

- Short sentences. Plain verbs: *deploy*, *roll back*, *retry*.
- State facts about status first, then the action. "Build failed. Retry?"
- Use `code` style for hashes, branch names and commands.

## Visual foundations

- **Color.** Neutral surfaces (`surface-100`, `surface-200`) carry most of the UI. `brand` is the one strong hue, for primary actions and links. `accent` signals a deploy in progress; `danger` marks failure. Put `ink` text on `accent`, and `on-brand` text on `brand` and `danger`.
- **Type.** Space Grotesk for everything readable, JetBrains Mono for code. Both are hosted on Google Fonts. Use `display` once per page at most.
- **Space.** An 8px rhythm: `space-2`, `space-4`, `space-6`, `space-10`.
- **Shape.** Mostly square. `radius-md` on buttons and cards, `radius-sm` on badges and inputs, `radius-lg` on modals.
- **Depth.** Borders, not shadows. Use the `line` hairline to separate.

## Iconography

No icon set yet. Until one is chosen, use a simple 1.5px stroke outline set in `ink` or `ink-muted`.
